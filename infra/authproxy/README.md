# Auth-прокси (SSO + серверный штамп identity)

Назначение: единая аутентификация для UI/бэкенда и MLflow; **серверно** проставляет
`X-Authenticated-User` (клиент задать не может). MLflow публикуется ТОЛЬКО через прокси.
См. [`../../docs/06_IDENTITY_AND_AUTH.md`](../../docs/06_IDENTITY_AND_AUTH.md).

## Что положить сюда (TODO при реализации)
- Конфиг прокси (oauth2-proxy / Authelia) с upstream на `mlflow:5000` и `backend:8000`.
- Настройку OIDC-провайдера (Keycloak/Dex) — issuer/client_id/secret из `.env`.
- Правило инъекции заголовка `X-Authenticated-User` из проверенного токена.
- Запрет проброса этого заголовка от клиента (срезать входящий, ставить только свой).

## Минимальный вариант для демо
Упрощённый reverse-proxy (FastAPI) с локальным JWT-issuer: логин по паролю из сида,
выдаёт короткоживущий per-user токен, валидирует и штампует личность. Это допустимо
для демо; для «боевого» — полноценный OIDC.
