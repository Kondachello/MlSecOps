# 13 — Runtime-защита (G7) и мониторинг (G6)

## 13.1 Инференс-сервисы

Каждая прод-модель — отдельный FastAPI-сервис (`src/serve/`), по микросервису на модель
(масштабируемость, изоляция). Общие runtime-защиты (G7) подключаются как middleware/слой.

```
[клиент] → [инференс FastAPI: G7 middleware] → [модель]
                         │
                      [Redis] rate-limit
```

## 13.2 G7 — Runtime Gate

| Защита | Механизм | Поведение |
|---|---|---|
| **RT-01 Rate limiting** (анти-extraction/DoS) | Redis-счётчик по API-key/IP | `>N req/min` → `429 Too Many Requests` |
| **DOS-01 Load-shedding** | глобальный семафор `MAX_INFLIGHT` (threading) | сверх лимита одновременных → `503` (ядро живо) |
| **DOW-01 Cost/token-quota** | бюджет «стоимости» на ключ за минуту | исчерпан → `429` |
| **RT-05 Валидация входа** | Pydantic-схема (`max_length`, `amount>0`, `0≤age≤120`) | нарушение → `422`; payload-лимит → `413` |
| **RT-02 OOD/adversarial-детект** | проверка диапазонов/соотношений (`ood_check`) | вход-выброс → `suspect=true` + Finding (не блок) |
| **RT-03 Output reduction** (анти-extraction/membership) | класс вместо сырых logits | `{"decision":"approve"}` вместо `0.8123491` |
| **DLP-01 DLP в логах** | middleware regex/Presidio перед записью | маскирование карт `****-1234`, ФИО |

> Все защиты имеют ID контроля (см. [`20_CONTROLS_COVERAGE.md`](20_CONTROLS_COVERAGE.md)).
> Реализованы в `src/serve/app.py`: `_limiter` (RT-01), `_inflight` (DOS-01), `cost_exceeded`
> (DOW-01), `ood_check` (RT-02), `reduce_output` (RT-03), `dlp_mask` (DLP-01). Срабатывания
> пишутся в Audit Trail через `audit.log_event` (БД A → иначе JSONL-фолбэк).

P3 (GenAI, если берём 4-ю модель): guardrails против prompt-injection, нормализатор Base64/Hex,
output-DLP системного промпта, квоты `max_tokens`/таймаут, HITL на деструктивные tools агента.

## 13.3 Скрипт атаки (демо)

`src/serve/attack_sim.py` — эмуляция Model Stealing/DoS: N параллельных запросов на выгрузку
данных. Ожидаемо: сервис начинает отдавать `429`; в дашборде — всплеск + алерт. Скрипт **не**
содержит реального вредоносного кода — только нагрузочные запросы к нашему же API.

## 13.4 G6 — Observability / мониторинг прода

Работает **постоянно** (не по кнопке), отдельный слой `src/monitor/`:

| Что мониторим | Механизм | Триггер |
|---|---|---|
| Data/Concept Drift | evidently / расчёт PSI на прод-трафике vs train | `PSI > 0.25` → DRIFT, событие+алерт |
| Деградация качества | сравнение метрик на эталоне | падение ниже порога |
| **Подмена модели в проде** | периодический ре-хэш запущенного артефакта ↔ реестр | mismatch → инцидент |
| Доступность/аномалии API | метрики из инференса | всплески ошибок/латентности |

Чтобы считать PSI, инференс-сервис **логирует фичи** (с DLP) в хранилище метрик; монитор
периодически их забирает. Результаты пишутся в `events` и видны в дашборде UI.

## 13.5 Связь с гейтами и историей

- Любое срабатывание G6/G7 → `finding` + `event` (видно в UI: «открыто/закрыто», по активу и по системе).
- Детект подмены/дрейфа может инициировать предложение об откате/retire (решение — MLSecOps).
