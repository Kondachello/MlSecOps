# 01 — Обзор проекта

## 1.1 Бизнес-контекст

Бизнес зарабатывает на ML — ровно до момента, пока модель не ломается или не становится
вектором атаки. Тогда деньги теряются: искажённый скоринг, утечка ПДн и штраф регулятора,
кража модели конкурентом, RCE через отравленные веса, простой из-за устаревших библиотек.

**MLOps** делает ML воспроизводимым, надёжным и удобным, но про безопасность знает мало
(«не храните секреты в коде» — и всё). **MLSecOps** живёт поверх MLOps: видит весь пайплайн,
понимает, что в проде, и поэтому может предвидеть угрозы и ловить инциденты в момент их
возникновения. Мы не патчим дыры постфактум — мы управляем безопасностью системы.

Боль, которую закрываем (типовые «грабли» индустрии):
- MLflow без RBAC, миллион уязвимостей, «общий аккаунт на всех».
- Прод на библиотеках пятилетней давности с десятками CVE.
- DS уволился 3 года назад — никто не может перевыпустить модель (нет lineage/версий).
- Модель `sharegpt_vicuna_unfiltered` от анонима в проде; pickle-веса исполняют код при загрузке.
- Никакой видимости: что в проде, чьё, какого уровня критичности — неизвестно.

## 1.2 Что мы строим

Безопасную MLOps-систему, собранную из блоков и склеенную практиками MLSecOps:

- **Реестр моделей и датасетов** с паспортом, версиями, Tier и lineage (данные↔код↔модель).
- **Единая неподделываемая история событий** (Audit Trail) — любое действие логируется.
- **CI/CD с Security Gate-ами (G0–G7)** — «плохое» не доходит до прода.
- **Security Gate перед продом + HITL** — критичные модели требуют ручного одобрения.
- **Runtime-защита** прод-инференса — rate-limit, валидация, DLP, output-reduction.
- **RBAC и неподделываемая идентичность** — кто что делал, видно и не подделать.
- **Полная видимость** в вебе: статус защищённости, находки, история, реестр.

Покрываем **весь жизненный цикл** ML-решения: от загрузки данных и требований — через
обучение, верификацию, деплой — до вывода из эксплуатации.

## 1.3 Цели по приоритету (от куратора и жюри)

Порядок приоритетов главного жюри (сверху вниз — важнее):

```
скан кода → реестр моделей → security gate перед продом → скан моделей →
версионирование → история → связка данные-код-модель → ролёвка →
подписи → сканы данных → security gate на закачку →
автоконвертация/запрет небезопасных форматов → рантайм
```

> **Дисциплина:** «сделайте минимум и потом расширяйте». Сначала цельный сквозной флоу,
> затем низковисящие фрукты, потом practice-maxxing.

Четыре обязательные «фичи для жюри»:
1. **Единая история событий** (таблица `events`, вывод в UI).
2. **Human-in-the-Loop** для критичных моделей (Tier=HIGH не уходит в прод без Approve).
3. **Отработка False Positives** (в UI видна причина блокировки = JSON-отчёт гейта).
4. **Runtime-защита** (Redis rate-limit, спам-скрипт → `429 Too Many Requests`).

## 1.4 В скоупе / вне скоупа

**В скоупе (MVP и расширения):**
- 3+ разных ML-решения (фокус на **не**(де)генеративном ИИ): напр. табличный кредитный
  скоринг, классификатор (изображения/текст), и третья классическая модель.
- Полный набор гейтов G0–G7 (минимум — P0, далее расширение).
- Реестр, Audit Trail, RBAC, HITL, runtime-защита, базовый мониторинг дрейфа.
- Всё поднимается одним `docker compose`; CI — GitHub Actions через self-hosted runner.

**Вне скоупа сейчас (будущий рост, возможно отдельным микросервисом):**
- Полноценная поддержка **GenAI** (LLM, RAG) и **агентских систем**. Архитектуру
  проектируем масштабируемой, чтобы добавить их позже без переделки ядра. Соответствующие
  угрозы (P3 в модели угроз) реализуем только если останется время.

## 1.5 Критерии успеха

- На демо за 10–15 минут проходит **цельный сквозной флоу** (не набор разрозненных кнопок):
  загрузка датасета → обучение → верификация → деплой → атака в рантайме → детект.
- Видно **роли** (DS, MLSecOps, …), историю событий, причины блокировок и реестр.
- Модель угроз читается **не только технарями** и отражает реальное положение дел.
- Всё поднимается одной командой; демо-сценарии запускаются легко.

## 1.6 Не-цели и принципы

- Не претендуем на «идеальную» систему: честно показываем **пределы** защиты
  (см. [`08_THREAT_MODEL.md`](08_THREAT_MODEL.md) §«Честные пределы»).
- Используем готовые решения, анализируя их безопасность и докручивая нужное
  (напр. MLflow без RBAC → ставим за auth-прокси).
- Безопасность — автоматическая фича системы, а не ручной ритуал.
