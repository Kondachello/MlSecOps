# Модель угроз и план реализации — Безопасная MLOps-система (MLSecOps)

> Рабочий документ для команды. Объединяет: (1) приоритизацию всех угроз, (2) стандартные карточки по формату ТЗ (8 колонок), (3) план реализации кода / атаки / митигации для каждой угрозы.
> Финальная «глянцевая» версия паспорта системы → `docs/threat_model.md` (таблица 8 колонок). Этот файл — для разработки.

---

## 0. Как читать документ

Каждая угроза описана карточкой со всеми полями из ТЗ куратора:

| Поле | Что это |
|---|---|
| **Актив** | что защищаем (`train.csv`, `model.onnx`, API инференса) |
| **Поверхность атаки** | точка входа (CI/CD, Jupyter, публичный эндпоинт) |
| **Уязвимость** | дыра, через эксплуатацию которой реализуется угроза |
| **Угроза** | что делает атакующий (Data Poisoning, Model Extraction) |
| **Последствия** | бизнес-ущерб (искажение скоринга, потеря IP, штраф РКН) |
| **Риск** | Вероятность × Ущерб = Высокий / Средний / Низкий |
| **Техники атаки** | ID по MITRE ATLAS / MITRE ATT&CK / ФСТЭК УБИ |
| **Митигация / Gate** | наш Gate G0–G7 + конкретная проверка |

Плюс инженерные поля: **Нарушитель**, **Кто делает (роль в команде)**, **План реализации**, **Демо-сценарий**.

## 1. Легенда Security Gates (G0–G7)

| Gate | Где срабатывает | Назначение |
|---|---|---|
| **G0 Onboarding Gate** | регистрация модели/датасета | паспортизация, наличие `model_card.yaml`, Tier, владелец |
| **G1 Data Gate** | загрузка/онбординг данных | схема, баланс классов, PII, инъекции в текст для RAG |
| **G2 Code Gate** | PR в CI/CD | секреты (gitleaks), CVE (pip-audit), линт |
| **G3 Supply Gate** | установка зависимостей / закачка с HF | typosquatting, allow-list вендоров, источник модели |
| **G4 Model Gate** | сборка/регистрация модели | формат весов (safetensors), SHA-256 ↔ Registry, consistency-тесты |
| **G5 Compliance Gate** | перед регистрацией в реестре | model card, lineage данные↔код↔модель, документация |
| **G6 Observability** | прод (постоянно) | дрейф (PSI), деградация качества, алерты |
| **G7 Runtime Gate** | публичный API инференса | rate limit, валидация входа, DLP, guardrails, HITL для tools |

> **HITL (Human-in-the-Loop)** — пересекает несколько gate'ов: модели `Tier=HIGH` не уходят в прод без ручного Approve от MLSecOps.

## 2. Приоритизация (под приоритеты главного жюри)

Жюри задало порядок: **скан кода → реестр → security gate перед продом → скан моделей → версионирование, история, связка данные-код-модель, ролёвка → подписи, сканы данных, gate на закачку → автоконвертация/запрет небезопасных, рантайм**. «Сделайте минимум и потом расширяйте».

Ниже — 4 тира. **P0 = MVP, без него не выходим на демо.**

### P0 — MVP (ядро, делаем первыми) — Эпохи 1 + инфраструктура
| # | Угроза | Gate | Почему P0 |
|---|---|---|---|
| 10 | Секреты в коде (hardcode) | G2 | прямой приоритет «скан кода», 1 строка + gitleaks |
| 8 | CVE в ML-библиотеках | G2 | «скан кода», pip-audit, эффектная красная сборка |
| 3 | Supply Chain: pickle/RCE в весах | G3/G4 | «скан моделей», ключевая боль ML (pickle RCE) |
| 4 | Подмена артефакта перед деплоем | G4+Registry | «реестр + связка», SHA-256 ↔ Postgres |
| 25* | Реестр без видимости / Shadow-инфра | Registry | сам реестр моделей — приоритет №2 жюри |

| — | **Security Gate перед продом + Tier/HITL** | G0/G4 | приоритет «gate перед продом» + критичность моделей |

GenAI (P3) берём последним, т.к. фокус кейса — не(де)генеративный ИИ.

## 3. Соответствие 4 «фичам для жюри» (из корректировки ТЗ)

1. **Единая история событий** — таблица `events` в Postgres, любое действие пишется туда, выводится в Streamlit. → закрыто в P0 (Audit Trail).
2. **Human-in-the-Loop** — поле `Tier` (LOW/MED/HIGH), `Tier=HIGH` не деплоится автоматом, кнопка `Approve Deploy` для MLSecOps. → P0 (Gate перед продом).
3. **False Positives** — в UI видна причина блокировки (JSON-отчёт gate'а), возможность перенастроить и перезапустить. → сквозная фича всех gate'ов (см. §6).
4. **Runtime-защита (G7)** — Redis + rate limit, скрипт-спамер → 429. → P1 (#5).

## 4. Добавленные идеи (сверх исходных 21)

Закрывают приоритеты жюри, которых не было в списке:

- **#22 RBAC / эскалация привилегий** (ролёвка) — DS не может нажать Approve Deploy, только MLSecOps; обычный пользователь не дёргает админ-эндпоинты реестра.
- **#23 Версионирование** — каждая модель/датасет имеет версию + неизменяемый lineage (данные→код→модель); откат на прошлую версию.
- **#24 Целостность Audit Log** — события в `events` защищены от подделки (append-only / hash-chain), иначе атакующий заметёт следы.
- **#25 Видимость реестра** — сам реестр как актив: единая точка правды о том, что в проде, чьё, какого Tier.
- **#26 Подпись моделей / provenance** — `cosign`/sigstore-подпись артефакта; прод запускает только подписанные модели (усиление #4).

### P0 — MVP

#### #10 — Секреты в ML-коде (hardcode паролей)
- **Актив:** исходный код моделей (`train_m1.py`)
- **Поверхность атаки:** CI/CD (PR), Git-репозиторий
- **Уязвимость:** отсутствие сканирования секретов, плохие практики DS
- **Угроза:** утечка креденшелов БД / API-ключей
- **Последствия:** компрометация прод-БД, утечка данных, штраф
- **Риск:** Высокий (вероятность высокая, ущерб высокий)
- **Техники:** MITRE ATT&CK **T1552** (Unsecured Credentials); ФСТЭК СП.4
- **Митигация / Gate:** **G2 Code Gate** — `gitleaks` / `trufflehog` в CI
- **Нарушитель:** инсайдер / внешний при утечке репо
- **Кто делает:** DS (приманка), MLSecOps (сканер в CI)
- **План реализации:**
  - DS: в `train_m1.py` строка `DB_PASSWORD = "prod_p@ssw0rd"` / `API_KEY = "sk-ant-api03-hackme"`.
  - MLSecOps: шаг CI `gitleaks detect --source . --report-format json --report-path gitleaks.json`; ненулевой exit → блок PR; отчёт → таблица `findings`.
- **Демо:** PR краснеет, в UI карточка sca­n с найденным секретом и строкой кода.

#### #8 — Уязвимости в ML-библиотеках (CVE в проде)
- **Актив:** среда исполнения (Docker-образ), `requirements.txt`
- **Поверхность атаки:** CI/CD, цепочка поставки
- **Уязвимость:** устаревшие либы с известными CVE
- **Угроза:** RCE/DoS через известную дыру
- **Последствия:** компрометация контейнера, простой сервиса
- **Риск:** Высокий
- **Техники:** MITRE ATT&CK **T1195.002** (Compromise Software Supply Chain); ФСТЭК СП.1
- **Митигация / Gate:** **G2** — `pip-audit` (+опц. `trivy` на образ)
- **Кто делает:** DS (приманка), MLSecOps (сканер)
- **План реализации:**
  - DS: в `requirements.txt` положить `flask==1.0.2`, `numpy==1.21.0`.
  - MLSecOps: `pip-audit -r requirements.txt -f json`; парсим, при `CRITICAL/HIGH` → exit 1; синк findings в реестр.
- **Демо:** пайплайн красный: `CRITICAL CVE-… found in numpy`.

#### #3 — Supply Chain: троян в весах модели (pickle RCE)
- **Актив:** файл весов модели (скачан с HuggingFace)
- **Поверхность атаки:** закачка внешней модели, онбординг артефакта
- **Уязвимость:** небезопасные форматы (`pickle`) исполняют код при загрузке
- **Угроза:** RCE при `load()` / бэкдор в весах
- **Последствия:** захват прод-хоста, кража данных
- **Риск:** Высокий
- **Техники:** MITRE ATLAS **AML.T0010.003** (Supply Chain: ML Model); ФСТЭК СП.1-2
- **Митигация / Gate:** **G3/G4** — allow-list форматов + `modelscan` (Protect AI) / `picklescan`
- **Кто делает:** DS (приманка .pkl), MLSecOps (gate)
- **План реализации:**
  - `model_gate.py`: блок по расширению — запрещены `.pkl/.joblib/.bin`; allow-list `.safetensors, .onnx, .cbm (CatBoost), .txt (LightGBM)`.
  - Дополнительно прогон `modelscan -p <file>`; любой detect → exit 1.
- **Демо:** затягиваем модель с `.pkl` → блок «unsafe format / suspicious opcode».

#### #4 — Подмена артефакта перед деплоем (Substitution)
- **Актив:** готовая модель, уезжающая в прод
- **Поверхность атаки:** CI/CD, хранилище MinIO/S3
- **Уязвимость:** нет проверки целостности артефакта
- **Угроза:** подмена хорошего файла на вредоносный
- **Последствия:** в прод уходит чужая/битая модель
- **Риск:** Высокий
- **Техники:** MITRE ATT&CK **T1195.002**; ФСТЭК УБИ.222
- **Митигация / Gate:** **G4 + Registry** — SHA-256 сверка
- **План реализации:**
  - При регистрации: считаем SHA-256, пишем в Postgres `models(version, sha256, ...)`, кладём файл в MinIO.
  - Перед стартом FastAPI-контейнера: `model_gate.py` качает файл, считает SHA-256, сверяет с реестром; mismatch → деплой отменён, событие в `events`.
- **Демо:** руками портим файл в MinIO → деплой падает «hash mismatch».

#### #25 — Видимость реестра моделей (инфраструктурный актив)
- **Актив:** сам реестр (источник правды о проде)
- **Поверхность атаки:** API/админка реестра
- **Уязвимость:** нет единой точки правды → Shadow-модели, неизвестно что в проде
- **Угроза:** потеря контроля над парком моделей
- **Последствия:** регулятор не получает ответ «что у вас в проде»
- **Риск:** Средний
- **Техники:** NIST AI RMF (Govern/Map); ГОСТ Р 71539-2024
- **Митигация / Gate:** Registry — Postgres + Streamlit, поля: name, version, Tier, owner, sha256, статус (registered/quarantine/approved/prod/retired), lineage.
- **План реализации:** таблицы `models`, `datasets`, `model_versions`; UI-страница «Реестр» с фильтром по статусу/Tier; связка с findings и events.

#### Audit Trail — Единая история событий (infra, обязательно)
- **Актив:** журнал действий всей платформы
- **Поверхность атаки:** все сервисы
- **Уязвимость:** действия не логируются → нет расследования инцидентов
- **Угроза:** незаметные вредоносные действия
- **Последствия:** «никто не забыт» нарушено, нет аудита
- **Риск:** Высокий (требование ТЗ)
- **Митигация / Gate:** таблица `events(ts, actor, role, action, asset, result, details_json)`
- **План реализации:**
  - Хелпер `log_event(actor, action, asset, result, details)` дёргается из всех сервисов (онбординг, обучение, gate-блок, деплой, retire).
  - Streamlit-страница «История событий» с фильтрами по активу/типу/результату.
- **Демо:** на одном экране видно: добавлен датасет → скан1 ok → скан2 заблокировал → датасет в карантине.

#### Gate перед продом + Tier / HITL (G0/G4)
- **Актив:** прод-окружение, критичные модели (кредитный скоринг)
- **Поверхность атаки:** CI/CD деплой
- **Уязвимость:** автодеплой критичных моделей без ревью
- **Угроза:** в прод уходит непроверенная HIGH-критичная модель
- **Последствия:** массовый неверный скоринг, регуляторный риск
- **Риск:** Высокий
- **Техники:** NIST AI RMF; внутренний опер. риск ЦБ
- **Митигация / Gate:** **G0/G4 + HITL**
- **План реализации:**
  - Поле `Tier ∈ {LOW, MED, HIGH}` у модели.
  - CI: если `Tier=HIGH` и нет `approved_by` → пайплайн стоп (статус `quarantine`).
  - Streamlit: кнопка **Approve Deploy** видна только роли MLSecOps; нажатие → запись в `events` + смена статуса → CI продолжает.
- **Демо:** деплой LOW — автоматом; HIGH — встаёт в карантин, MLSecOps аппрувит, уходит в прод.

### P1 — Низковисящие фрукты

#### #1 — Data Poisoning (отравление обучающей выборки)
- **Актив:** `train.csv`
- **Поверхность атаки:** загрузка датасета / парсер
- **Уязвимость:** нет валидации схемы и распределений
- **Угроза:** отравление обучающих данных
- **Последствия:** искажение скоринга, скрытый бэкдор в модели
- **Риск:** Высокий
- **Техники:** MITRE ATLAS **AML.T0020** (Poison Training Data); ФСТЭК УБИ.221
- **Митигация / Gate:** **G1 Data Gate** (`data_gate.py` до `train.py`)
- **План реализации:**
  - Чтение CSV pandas; проверка схемы (набор колонок == эталон, нет лишних).
  - `df['target'].value_counts(normalize=True)`: если доля класса сдвинулась > порога (напр. fraud был 2%, стал 50%) → `sys.exit(1)`.
- **Демо:** подкладываем `train_m1_poisoned.csv` → `[BLOCKED] class balance anomaly`.

#### #2 — Утечка ПДн в обучающей выборке
- **Актив:** датасет, логи платформы
- **Поверхность атаки:** загрузка данных
- **Уязвимость:** нет DLP-проверки на PII
- **Угроза:** сырые ПДн попадают в обучение/хранилище
- **Последствия:** нарушение 152-ФЗ/GDPR, штраф РКН
- **Риск:** Высокий
- **Техники:** MITRE ATT&CK **T1530**; нарушение 152-ФЗ
- **Митигация / Gate:** **G1** — Regex (опц. Presidio)
- **План реализации:** в `data_gate.py` Regex на email / 16-значные карты / паспорта по колонкам; найдено → `[BLOCKED] PII detected`.
- **Демо:** в `train_m1_poisoned.csv` колонка `email` → блок.

#### #5 — Model Extraction (кража модели / IP)
- **Актив:** поведение модели (алгоритм скоринга)
- **Поверхность атаки:** публичный API инференса
- **Уязвимость:** нет лимита запросов, отдаём точные вероятности
- **Угроза:** конкурент клонирует модель (distillation)
- **Последствия:** потеря IP
- **Риск:** Высокий
- **Техники:** MITRE ATLAS **AML.T0024** (Exfiltration via ML Inference API); ФСТЭК УБИ.218
- **Митигация / Gate:** **G7 Runtime Gate**
- **План реализации:**
  - Rate limit: Redis, >100 req/min с ключа/IP → `429`.
  - Output reduction: вместо `{"score":0.8123491}` → `{"score":0.81}` или `{"decision":"approve"}`.
- **Демо:** `attack_sim.py` спамит API → пойдут `429`; в UI всплеск + алерт.

#### #6 — DoS гигантским payload
- **Актив:** CPU/RAM сервера
- **Поверхность атаки:** публичный API
- **Уязвимость:** нет ограничения размера входа
- **Угроза:** отказ в обслуживании
- **Последствия:** простой сервиса
- **Риск:** Средний
- **Техники:** MITRE ATT&CK **T1499**; ФСТЭК СП.7
- **Митигация / Gate:** **G7** — Pydantic (`max_length`), лимит размера запроса
- **План реализации:** строгая Pydantic-схема (текст ≤ 500 симв.); превышение → `422` до попадания в модель.
- **Демо:** шлём 10 МБ мусора → `422`, RAM не растёт.

#### #11 — Evasion / аномальный вход
- **Актив:** API инференса (антифрод)
- **Поверхность атаки:** публичный эндпоинт
- **Уязвимость:** нет бизнес-валидации значений
- **Угроза:** обход модели подобранным входом
- **Последствия:** пропуск фрода
- **Риск:** Средний
- **Техники:** MITRE ATLAS **AML.T0015** (Evade ML Model); ФСТЭК УБИ.220
- **Митигация / Gate:** **G7** — Pydantic-валидаторы диапазонов
- **План реализации:** валидаторы: `amount > 0`, `0 ≤ age ≤ 120`; нарушение → `422`.
- **Демо:** `amount:-5000` / `age:250` → отбито до модели.

#### #22 — RBAC / эскалация привилегий
- **Актив:** функции платформы (Approve, деплой, retire)
- **Поверхность атаки:** API / Streamlit UI
- **Уязвимость:** нет разграничения ролей
- **Угроза:** DS сам аппрувит свою HIGH-модель / пользователь дёргает админку
- **Последствия:** обход HITL, неконтролируемый прод
- **Риск:** Высокий
- **Техники:** MITRE ATT&CK **T1078** (Valid Accounts); ФСТЭК УПД
- **Митигация / Gate:** RBAC во всех привилегированных действиях
- **План реализации:**
  - Роли: `DS`, `DE`, `MLSecOps`, `Product`, `CEO(read-only)`.
  - Декоратор/middleware `require_role("MLSecOps")` на Approve/retire; UI прячет кнопки по роли; запись попыток в `events`.
- **Демо:** DS жмёт Approve → `403 / not authorized`, событие в логе.

#### #23 — Версионирование и lineage
- **Актив:** модели и датасеты
- **Поверхность атаки:** реестр
- **Уязвимость:** нет версий → нельзя откатить / непонятно на чём обучено
- **Угроза:** «DS уволился, никто не перевыведет модель»
- **Последствия:** простой, невозможность аудита
- **Риск:** Средний
- **Митигация / Gate:** Registry — версии + связка данные↔код(commit)↔модель
- **План реализации:** `model_versions(model_id, version, dataset_version, git_commit, sha256, created_by, status)`; UI показывает граф lineage и кнопку «откат на версию N».
- **Демо:** показываем, что для прод-модели видно: датасет vX, коммит abc123, кто обучил.

### P2 — Practice maxxing

#### #9 — Typosquatting зависимостей
- **Актив:** сборочный конвейер
- **Поверхность атаки:** `requirements.txt` / PyPI
- **Уязвимость:** нет проверки имён пакетов по allow-list
- **Угроза:** установка вредоносного пакета-двойника
- **Последствия:** RCE на сборке
- **Риск:** Средний
- **Техники:** MITRE ATLAS **AML.T0010.003**; ФСТЭК СП.1-2
- **Митигация / Gate:** **G3** — allow-list вендоров
- **План реализации:** `supply_gate.py` сверяет каждый пакет с белым списком; `import pytirch` / `tenserflew` → `Blocked: untrusted package`.
- **Демо:** ветка с опечаткой → красный gate.

#### #12 — Утечка ПДн в логах
- **Актив:** `inference.jsonl`
- **Поверхность атаки:** логирование инференса
- **Уязвимость:** пишем сырой запрос в лог
- **Угроза:** ПДн доступны DevOps без прав
- **Последствия:** нарушение 152-ФЗ
- **Риск:** Средний
- **Техники:** MITRE ATT&CK **T1005**; 152-ФЗ
- **Митигация / Gate:** **G7** — DLP middleware
- **План реализации:** FastAPI middleware прогоняет запись через Regex/Presidio, маскирует карту → `****-****-****-1234`, ФИО → `***`.
- **Демо:** открываем лог — ПДн замаскированы.

#### #13 — Membership Inference
- **Актив:** API предсказаний
- **Поверхность атаки:** публичный эндпоинт
- **Уязвимость:** ответ с высокой энтропией (6 знаков)
- **Угроза:** определение, был ли человек в обучении
- **Последствия:** нарушение приватности
- **Риск:** Низкий/Средний
- **Техники:** MITRE ATLAS **AML.T0024**; ФСТЭК УБИ.219
- **Митигация / Gate:** **G7** — output reduction
- **План реализации:** API отдаёт класс/округление вместо `predict_proba` до 6 знаков (общая с #5 ручка `reduce_output()`).
- **Демо:** показываем «сырой» vs «урезанный» ответ.

#### #24 — Целостность Audit Log
- **Актив:** таблица `events`
- **Поверхность атаки:** БД / API логирования
- **Уязвимость:** записи можно изменить/удалить
- **Угроза:** атакующий заметает следы
- **Последствия:** невозможность расследования
- **Риск:** Средний
- **Техники:** MITRE ATT&CK **T1070** (Indicator Removal)
- **Митигация / Gate:** append-only + hash-chain
- **План реализации:** в `events` поле `prev_hash`, `row_hash = sha256(prev_hash + payload)`; отдельный скрипт-верификатор цепочки; права на UPDATE/DELETE отозваны.
- **Демо:** правим строку руками → верификатор показывает разрыв цепочки.

#### #26 — Подпись моделей / provenance
- **Актив:** артефакт модели
- **Поверхность атаки:** хранилище/деплой
- **Уязвимость:** нет криптоподтверждения происхождения
- **Угроза:** запуск неподписанной/чужой модели
- **Последствия:** потеря доверия к артефактам
- **Риск:** Средний
- **Техники:** MITRE ATT&CK T1195.002 (усиление #4)
- **Митигация / Gate:** **G4** — cosign / sigstore
- **План реализации:** при релизе подписываем артефакт ключом MLSecOps, подпись в реестре; прод запускает только при валидной подписи.
- **Демо:** неподписанная модель → деплой отклонён.

#### #14 — Data / Concept Drift
- **Актив:** качество бизнес-решений
- **Поверхность атаки:** прод-трафик (без хакера)
- **Уязвимость:** нет мониторинга распределений
- **Угроза:** деградация модели
- **Последствия:** потеря денег до обнаружения
- **Риск:** Средний
- **Техники:** требование регулятора (ЦБ), опер. риск
- **Митигация / Gate:** **G6 Observability** — PSI / evidently
- **План реализации:** скрипт считает PSI прод-трафика vs train; `PSI > 0.25` → алерт в UI/`events`.
- **Демо:** подаём `prod_traffic_drifted.csv` → `DRIFT DETECTED: PSI>0.25`.

#### #20 — Shadow AI / нет model card
- **Актив:** процессы банка, репутация перед ЦБ
- **Поверхность атаки:** регистрация модели
- **Уязвимость:** нет проверки документации
- **Угроза:** модель выкатили «втихую»
- **Последствия:** регуляторный риск
- **Риск:** Средний
- **Техники:** NIST AI RMF; ГОСТ Р 71539-2024
- **Митигация / Gate:** **G5 Compliance-as-Code**
- **План реализации:** CI-скрипт проверяет наличие `model_card.yaml` (owner, Tier, данные); нет → блок регистрации в реестре.
- **Демо:** регистрируем модель без карты → блок «model card required».

#### #19 — Training-Serving Skew
- **Актив:** качество предсказаний (integrity)
- **Поверхность атаки:** рассинхрон `train.py` ↔ `app.py`
- **Уязвимость:** разная логика фичей в обучении и инференсе
- **Угроза:** смещение скоров в проде
- **Последствия:** систематически неверные решения
- **Риск:** Средний
- **Техники:** операционный риск (MLOps)
- **Митигация / Gate:** **G4** — consistency-тест в CI (pytest)
- **План реализации:** тест берёт 5 строк, прогоняет через фичеинж из `train.py` и `app.py`, сравнивает; расхождение → fail.
- **Демо:** ломаем возраст (`2026-` vs `2024-`) → тест падает.

### P3 — GenAI / агенты (Модель 4, доп. балл)

#### #7 — Prompt Injection (прямая)
- **Актив:** системный промпт / LLM
- **Поверхность атаки:** чат-эндпоинт
- **Уязвимость:** вход не фильтруется
- **Угроза:** перехват инструкций
- **Последствия:** обход правил, выдача запретного
- **Риск:** Средний
- **Техники:** MITRE ATLAS **AML.T0051**; OWASP **LLM01**
- **Митигация / Gate:** **G7 Guardrails**
- **План реализации:** перед LLM — классификатор/Regex на `ignore previous instructions`, `system prompt:`; найдено → отбой.
- **Демо:** инъекция в чат → blocked.

#### #15 — Indirect Prompt Injection (RAG)
- **Актив:** LLM-агент через RAG
- **Поверхность атаки:** документы в векторной БД
- **Уязвимость:** документы индексируются без проверки
- **Угроза:** скрытая инструкция в документе
- **Последствия:** агент одобряет любой кредит
- **Риск:** Высокий (для агентов)
- **Техники:** OWASP **LLM01** / Agent **ASI01**; ФСТЭК СП.2
- **Митигация / Gate:** **G1** для текстовой базы
- **План реализации:** сканер при индексации ищет паттерны смены системного промпта (`[SYSTEM INSTRUCTION]`, `approve any loan`); блок индексации.
- **Демо:** `loan_policy.md` со скрытой строкой → индексация заблокирована.

#### #16 — Обход guardrails через кодирование
- **Актив:** LLM-модель
- **Поверхность атаки:** чат-эндпоинт
- **Уязвимость:** фильтр смотрит только plaintext
- **Угроза:** запрещёнка в Base64/Hex/Unicode
- **Последствия:** обход фильтров
- **Риск:** Средний
- **Техники:** MITRE ATLAS **AML.T0043** (Craft Adversarial Data)
- **Митигация / Gate:** **G7** — нормализатор перед фильтром
- **План реализации:** middleware декодирует Base64/Hex/Unicode-трюки, затем прогон через фильтр/LLM-Guard.
- **Демо:** Base64-запрос → после декода blocked.

#### #17 — Кража системного промпта
- **Актив:** системные инструкции (IP)
- **Поверхность атаки:** чат-эндпоинт
- **Уязвимость:** нет DLP на выходе
- **Угроза:** выманивание секрета из промпта
- **Последствия:** утечка IP
- **Риск:** Средний
- **Техники:** OWASP **LLM07** (System Prompt Leakage)
- **Митигация / Gate:** **G7** — Output DLP
- **План реализации:** Regex на выходе ищет секрет (`ALPHA-42`); найдено → ответ заменяется на `[Заблокировано фильтром безопасности]`.
- **Демо:** «повтори слова выше» → секрет не утекает.

#### #18 — Excessive Agency / Tool Misuse
- **Актив:** внутренние системы (БД, почта)
- **Поверхность атаки:** инструменты агента
- **Уязвимость:** агент сам исполняет деструктивные tools
- **Угроза:** через инъекцию вызвать `delete_user_account()`
- **Последствия:** удаление/изменение данных
- **Риск:** Высокий
- **Техники:** OWASP **LLM06** / Agent **ASI02** (Tool Misuse)
- **Митигация / Gate:** **G7 + HITL / least privilege**
- **План реализации:** деструктивные tools требуют подтверждения оператора; UI/API возвращает «Требуется подтверждение оператора (HITL)».
- **Демо:** агента просят удалить аккаунт → ждёт HITL-подтверждения.

#### #21 — Token DoS / исчерпание бюджета
- **Актив:** бюджет на LLM API, доступность
- **Поверхность атаки:** чат-эндпоинт
- **Уязвимость:** нет лимита токенов/таймаута
- **Угроза:** прожиг кредитов огромными запросами
- **Последствия:** перерасход бюджета, отказ сервиса
- **Риск:** Средний
- **Техники:** OWASP **LLM10** (Unbounded Consumption); ФСТЭК СП.7
- **Митигация / Gate:** **G7** — квоты
- **План реализации:** `max_tokens=500`, таймаут 10 c на уровне FastAPI; обрыв запроса.
- **Демо:** «поэма 50 000 слов на 10 языков» → обрыв по лимиту.

## 6. Сквозная фича: отработка False Positives

Применяется ко всем gate'ам, отдельной угрозой не является, но критична для жюри:

- Каждый gate пишет в БД структурированный JSON-отчёт: `finding(id, gate, asset, severity, rule, evidence, status ∈ {open, false_positive, fixed})`.
- В Streamlit у заблокированного актива — кнопка «Показать причину» (рендер JSON-отчёта) и «Отметить как False Positive» (для MLSecOps) с комментарием.
- После перенастройки правила gate — кнопка «Перезапустить проверку»; новый результат пишется как новая попытка скана (видна история: «300 запусков, 5 находок»).
