# 02 — Глоссарий

| Термин | Определение |
|---|---|
| **MLOps** | Практики автоматизации жизненного цикла ML: воспроизводимость, версионирование, деплой, мониторинг. |
| **MLSecOps** | Слой безопасности поверх MLOps: видимость пайплайна, гейты, контроль угроз, runtime-защита. |
| **Gate (G0–G7)** | Автоматическая проверка на конкретной стадии. `PASS` пропускает дальше, `FAIL` блокирует. Каждый гейт — отдельный Docker-образ. |
| **Gatekeeper** | Бэкенд (FastAPI), единая точка, которая по запросу запускает связку гейтов (deep audit) и согласует результат с реестром/историей. |
| **Finding (находка)** | Структурированная сработка гейта: что нашли, severity, evidence, статус. Таблица `findings`. |
| **Event (событие)** | Запись в Audit Trail (`events`), защищена hash-chain, неподделываема. |
| **Audit Trail** | Единая история всех действий платформы. «Никто не забыт, ничто не упущено». |
| **hash-chain** | Цепочка хэшей записей лога (`row_hash = sha256(prev_hash + payload)`) — делает подделку истории заметной. |
| **Tier** | Критичность модели: `LOW` / `MED` / `HIGH`. `HIGH` требует ручного одобрения (HITL). Назначается авто-правилами или MLSecOps. |
| **HITL** (Human-in-the-Loop) | Ручной контроль: модель встаёт в карантин, MLSecOps валидирует и нажимает Approve. Обязателен для `Tier=HIGH` и для внешних весов. |
| **Lineage** | Неразрывная связка: данные (версия + хэш) ↔ код (git SHA) ↔ модель (версия + хэш + run_id). |
| **Quarantine (карантин)** | Зона для заблокированных артефактов. Не удаляются — хранятся как улика для атрибуции. |
| **WORM** | Write Once Read Many. Режим неизменяемости хранилища (MinIO Object Lock) для прод-артефактов. |
| **Model Card (паспорт модели)** | Метаданные модели: owner, Tier, назначение, источник данных, lineage, версии, история проверок. |
| **CI-обучение** | Обучение модели внутри CI-джобы из проверенного кода и данных. **Канонический** способ получить прод-артефакт. |
| **Внешние веса** | Модель, скачанная готовой (HuggingFace/Kaggle) без обучения у нас. Получает метку источника, проходит все применимые гейты, обязательный HITL. |
| **Self-hosted runner** | Раннер GitHub Actions, поднятый локально (в `docker compose`), чтобы джобы CI исполнялись на машине демо. |
| **alias (MLflow)** | Метка версии модели: `candidate` → `staging` → `production`. Релиз = смена alias, а не ручная заливка. |
| **Data Digest** | Цифровой слепок датасета (SHA-256 + профиль), вычисляется `mlflow.data.from_pandas(...)`. |
| **verified_datasets** | Реестр уже проверенных датасетов (по хэшу) для быстрого повторного использования (fast-path). |
| **G2 SCA / SAST** | SCA = анализ состава ПО (CVE зависимостей, pip-audit). SAST = статанализ кода (bandit). |
| **Output reduction** | Урезание ответа модели (класс/округление вместо сырых вероятностей) против extraction/membership-атак. |
| **DLP** | Data Loss Prevention. Маскирование ПДн/секретов в логах и ответах. |
| **Drift / PSI** | Смещение распределения данных в проде. PSI (Population Stability Index) > 0.25 → алерт. |
| **Blue-green** | Стратегия замены прод-сервиса: поднять новый рядом, проверить, переключить трафик, погасить старый, с возможностью отката. |
| **RBAC** | Role-Based Access Control. Привилегированные действия (Approve/retire/export/promote) — только по роли. |
| **SSO** | Single Sign-On: один аккаунт на UI/бэкенд и MLflow с согласованной идентичностью. |
| **cosign / sigstore** | Инструмент криптоподписи артефактов и контейнерных образов (provenance). |
| **modelscan / picklescan** | Сканеры артефактов модели на вредоносные opcode/импорты (анти-pickle-RCE). |
| **trivy** | Сканер уязвимостей файловой системы и Docker-образов. |
| **gitleaks** | Сканер секретов в коде/истории git. |
| **Роли** | `DS` (Data Scientist), `DE` (Data Engineer), `MLSecOps` (админ безопасности), `Product`, `CEO` (read-only). |
