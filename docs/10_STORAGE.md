# 10 — Хранилище (MinIO / S3)

## 10.1 Бакеты

| Бакет | Назначение | Особенности |
|---|---|---|
| `datasets` | чистые проверенные датасеты | доступ по RBAC (`dataset_access`) |
| `quarantine` | заблокированные артефакты (данные/модели) | **не удаляем** — улика для атрибуции |
| `models` | артефакты моделей | префикс `prod/*` — WORM |
| `mlflow` | artifact-store MLflow | отдельный бакет |

> Важно: MLflow **не** перекладывает файлы между бакетами по статусу безопасности. Статус
> хранится в Postgres (см. [`09_DATA_MODEL.md`](09_DATA_MODEL.md)); в MinIO — фиксированные бакеты.

## 10.2 Схема ключей

```
<bucket>/<name>/<version>/<sha12>_<filename>
```
Пример: `models/credit_scoring/4/a1b2c3d4e5f6_model.safetensors`.
Прод-копия: `models/prod/credit_scoring/4/...` (под WORM-политикой).

## 10.3 Неизменяемость прода (WORM)

Требование: «прод-модель и её данные нельзя удалить/модифицировать».

Реализация:
1. **MinIO Object Lock** (WORM) включается на прод-префиксе/бакете при выкатке (режим
   `GOVERNANCE`/`COMPLIANCE` + retention). Перезапись/удаление объекта запрещены.
2. **Bucket policy** запрещает `s3:DeleteObject`/overwrite для прод-префикса роли приложения.
3. **Уровень приложения:** бэкенд отказывает в мутациях объектов со статусом `prod`; датасет
   под прод-моделью получает статус `prod_locked` и не принимает обновления (только копия).
4. **Старые версии не удаляются** — нужны для отката (`previous`).

## 10.4 Поток размещения

| Событие | Куда кладём |
|---|---|
| Датасет прошёл G1 | `datasets/...`, статус `available` |
| Датасет не прошёл G1 | `quarantine/...`, статус `quarantine` (+ finding) |
| Внешние веса (ingest) | сразу заморозить (SHA) → `quarantine/...` `pending_hitl` |
| CI-артефакт обучен | `mlflow` (через MLflow) + `models/...` candidate |
| Деплой в прод | копия в `models/prod/...` под WORM + cosign-подпись |
| Заблокировано на любом гейте | `quarantine/...` (никогда не удаляем) |

## 10.5 Целостность при чтении

Перед использованием артефакта (особенно перед `docker run` инференса) бэкенд/деплой:
1. скачивает объект,
2. пересчитывает SHA-256 и сверяет с `models.sha256` / `model_versions.sha256`,
3. проверяет cosign-подпись,
4. при несовпадении — отказ + событие `error`/`blocked`.
