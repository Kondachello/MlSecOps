## 1. Что это за продукт

**MLSecOps Platform** — «контур безопасности» над MLOps. На каждом шаге жизни модели (данные →
код → обучение → артефакт → реестр → деплой → прод) стоит автопроверка (Security Gate); всё
пишется в неподделываемую историю (Audit Trail); критичные модели (Tier=HIGH) требуют ручного
одобрения человеком (HITL). Безопасность — встроенная фича, а не патч.

**Центральная модель — артефакто-центричная.** Единица всего — **артефакт = MLflow run =
«сессия разработки»** (данные + код + модель в одном ноутбуке). «Реестр» — хаб артефактов,
разложенных по **зонам жизненного цикла**. Открываешь артефакт → его «паспорт»: метаданные,
цепочка гейтов с логами, перезапуск проверки, и (для MLSecOps) выкатка/одобрение/прод.

Историческое деление: **A** — ядро (БД, авторизация, бэкенд, MLflow-интеграция), **B** — гейты
G1–G5 + CI, **C** — модели/рантайм/мониторинг/UI. Текущая база — слитая: ядро A + гейты B +
объединённый артефакто-центричный UI.

## 2. Роли (RBAC)

Роль не выдаётся при саморегистрации — её назначает только **MLSecOps**.

| Роль | Кто | Что делает | Клиренс |
|---|---|---|---|
| **DS** | разработчик моделей | эксперименты в MLflow, security check своих артефактов, открытие доступа, выкатка-запрос | 1 |
| **DE** | инженер данных | загрузка/версионирование датасетов | 1 |
| **Product** | продакт | смотрит реестр/историю/дашборд (read) | 2 |
| **MLSecOps** | админ безопасности | роли/доступы, ревью всех сабмиченных артефактов, HITL-Approve, выкатка в прод, триаж инцидентов | 3 |
| **CEO** | топ-менеджмент | read-only дашборд + карта покрытия | 4 |

**Клиренс** — для шаринга артефактов по read-down (старшая роль видит расшаренное младшей).
**Разделение полномочий:** MLSecOps не может подтвердить (Approve) собственный артефакт.

## 3. Жизненный цикл артефакта и зоны реестра

```
лог в MLflow → [артефакт приватен] → security check (цепочка гейтов G1..G5)
   PASS → зона OK → (MLSecOps) Выкатка → [Tier=HIGH? Human Approve : авто] → Промоушен → ПРОД
   FAIL → зона «Не прошли» + Инцидент(ы)
   из ПРОДА → Откат (previous) / Вывод из эксплуатации (retired)
```

**Зоны реестра** (вычисляются по статусу проверки + стадии выкатки):

| Зона | Когда | 
|---|---|
| 🗂 Черновики (свалка) | артефакт ещё не проверяли (`check none/pending`) |
| ⛔ Не прошли проверку | security check FAIL |
| ✅ Прошли проверку | security check PASS, ещё не в выкатке |
| 🚀 Выкатка / на согласовании | инициирована выкатка (`pending_approve` HITL / `approved`) |
| 🟢 В проде | промоутнут в прод |
| ⏮ Предыдущие | откат из прода |
| 🗄 Выведены | retired |

**Security Gates** (цепочка задаётся в `config/gates.yml`, прогоняется при security check):

| Gate | Что проверяет | Угрозы | Статус |
|---|---|---|---|
| G1 Data | схема, баланс классов, PII, инъекции | #1 #2 #11 #15 | 🟡 в цепочке (плейсхолдер PASS); отдельный реальный G1 — кнопкой «Инструменты»? нет, см. ниже |
| G2 Code | секреты, CVE, SAST | #8 #10 | 🟡 в цепочке (плейсхолдер) |
| G3 Supply | typosquatting, пиннинг, источник | #9 #3 | 🟡 в цепочке (плейсхолдер) |
| G4 Model | формат весов (анти-pickle), скан, SHA, подпись | #3 #4 #26 | 🟡 в цепочке (плейсхолдер) |
| G5 Registry | паспорт, lineage, Tier | #20 #23 | 🟡 в цепочке (плейсхолдер) |
| G6/G7 | рантайм: дрейф/подмена, кража/DoS/утечки | #14 #5 #6 #11 #12 | 🚧 код «C» в репо, в стенд не поднят |

> Цепочка гейтов сейчас — **конфиг-driven плейсхолдер**: структура (G1→…→G5), per-gate логи,
> severity и привязка к угрозам реальные, но логика гейтов отдаёт PASS (`result: pass` в YAML).
> Реальные G1/G2/G3 как отдельные сканеры доступны в CI (`/ci/trigger`, gitleaks/bandit/pip-audit).

## 4. Реализованный функционал

### 4.1 Аутентификация и роли ✅
Саморегистрация (без роли) → логин → JWT (8ч, годен и для MLflow через прокси) → MLSecOps
назначает роль. Bootstrap-админ `msecops`/`admin-pass` (`infra/seed_admin.py`).

### 4.2 Кабинет разработчика ✅
`/auth/me`, кнопка «Получить MLflow-токен» (сниппет для Jupyter), таблица последних MLflow-ранов.

### 4.3 Изоляция и приватность в MLflow ✅
Каждый DS работает в своём эксперименте; раны приватны по умолчанию. Личность владельца
**неподделываема** (auth-прокси штампует `mlsecops.owner` из токена). Фильтрация видимости — и в
нашем UI, и в самом MLflow через прокси (чужое приватное вырезается; прямой запрос → 403).

### 4.4 Security check = цепочка гейтов 🟡 ✅(поток)
Кнопка «Security check» (владелец) или «Перепройти» на странице артефакта → прогон цепочки
G1..G5 из `config/gates.yml`. Результат — паспорт проверки (цепочка со статусами, severity,
угрозами, **логами** по каждому гейту). Можно **перезапустить отдельный гейт**. Назначается
**Tier** (LOW/MED/HIGH; HIGH — по эвристике имени/эксперимента: credit/fraud/scoring/…).
Каждый FAIL-гейт автоматически заводит **инцидент**.

### 4.5 Контролируемый шаринг артефактов ✅
После успешной проверки владелец может «Открыть доступ» — по клиренсу роли (read-down) или
кастомному списку ролей; «Закрыть доступ» — снова приватно. Всё в Audit Trail.

### 4.6 Реестр — хаб артефактов по зонам ✅
Реальные MLflow-раны + ACL, разложенные по зонам (см. §3). **Фильтры по тегам (security.*) и
статусам** (зона / статус проверки / Tier / владелец). MLSecOps как ревьюер видит все артефакты,
попавшие в пайплайн (на которых запускали проверку); приватные черновики до проверки — только
владельцу. Из реестра открывается страница артефакта.

### 4.7 Выкатка и HITL (жизненный цикл) 🟡 ✅(поток)
На странице артефакта (RBAC: MLSecOps): **Выкатка** → для Tier=HIGH стадия `pending_approve`
(ждёт Human Approve), для остальных сразу `approved`; **Approve** (HITL, не владелец) → `approved`;
**Промоушен** → `prod` (прежний прод эксперимента → `previous`); **Откат** → `previous`;
**Вывод** → `retired`. **Реального CI-деплоя нет (плейсхолдер), но движение стадий
персистится и видно** в реестре и на дашборде. Дашборд MLSecOps показывает очередь
**«Ожидают Human Approve»**.

### 4.8 Инциденты ✅
Раздел «Инциденты» — сработки безопасности, автоматически из упавших гейтов (severity, гейт,
правило, evidence, статус). Фильтры по гейту/severity/статусу. MLSecOps может отметить
**false positive**; «Открыть артефакт →» ведёт на страницу артефакта. (Гейты-плейсхолдеры обычно
проходят → список обычно пуст; падение гейта мгновенно наполняет его.)

### 4.9 История (Audit Trail) ✅
Неподделываемая цепочка (hash-chain), новые сверху. **Фильтры по тегам** (тип события / результат /
роль актора) — не по поисковой строке. Кнопка «Проверить цепочку» (целостность, угроза #24).

### 4.10 Сканеры в CI ✅
`/ci/trigger` — реальный запуск G1/G2/G3 (data/code/dependency) локально или в GitHub Actions
(`repository_dispatch`). Загрузка CSV. (Кнопочный раннер остался на бэкенде; в UI основной путь —
цепочка гейтов на странице артефакта.)

### 4.11 Админка ✅
Пользователи + роли, создание юзеров, выдача доступа к датасету (`can_export`).

### 4.12 GRC: Карта покрытия и Контур ✅
Каталог из 30 контролей (угроза→контроль→тест→стандарты ATLAS/OWASP/NIST/ФСТЭК), 25 live (83%);
RiskAcceptance (MLSecOps). Контур — сводка рантайм-защит + число открытых инцидентов.

### 4.13 Дашборд ✅
Реальные счётчики (в проде / прошли проверку / открытые инциденты / события), очередь HITL
(MLSecOps), статус целостности аудита (CEO). Блок рантайм-метрик (PSI/429) — 🚧 (нужен слой C).

## 5. Физическое хранение артефактов

- **Сейчас:** байты артефактов хранит **MLflow artifact store** — локально (`./mlruns` или
  `%USERPROFILE%\mlsec_mlflow\artifacts`), в compose — бакет **`mlflow` в MinIO (S3)**.
- **Зоны — логические:** стадия/статус в нашей БД (`artifact_acl`), а не физическое перемещение.
- **План:** прод/одобренные артефакты → **WORM-копия в S3/MinIO** (Object Lock), под контролем
  MLflow + нашего сервиса (см. `core/storage.py`, 🚧). Деплой-операции сейчас плейсхолдер —
  реального копирования в прод-бакет и подписи (cosign) пока нет.

## 7. Сквозные сценарии (работают)

**A. Онбординг:** регистрация → MLSecOps выдаёт роль DS.
**B. Разработчик:** Кабинет → MLflow-токен → лог ранов из ноутбука (`examples/dev_train_mock.py`) →
«Мои артефакты»/«Реестр» → Security check (цепочка гейтов, Tier) → Открыть доступ.
**C. Реестр/жизненный цикл (MLSecOps):** Реестр → фильтры по зонам/тегам → открыть артефакт →
паспорт + цепочка гейтов (логи, перезапуск гейта) → Выкатка → (HIGH: Human Approve) → Промоушен →
Прод; видно движение по зонам и на дашборде.
**D. Инциденты:** упавший гейт → инцидент → триаж/FP.
**E. CEO:** read-only дашборд + карта покрытия.

> Демо-подсказка: эксперимент с именем-намёком (`credit_scoring`, `fraud_*`) → Tier **HIGH** →
> попадает в очередь Human Approve. Обычные (`*_research`) → MED → выкатка без HITL.
> HITL-Approve делает MLSecOps, **отличный от владельца** (разделение полномочий).
