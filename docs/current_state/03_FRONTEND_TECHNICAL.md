# MLSecOps Platform — Техническое описание фронтенда (текущее состояние)

> Дата среза: 2026-06-04 (артефакто-центричный рефакторинг). Объединённый Streamlit-UI
> (`ui/app.py`, один файл). Бизнес — [`01_BUSINESS_AND_FEATURES.md`](01_BUSINESS_AND_FEATURES.md),
> бэк — [`02_BACKEND_TECHNICAL.md`](02_BACKEND_TECHNICAL.md). Легенда: ✅ реальные данные · 🟡 поток
> реальный/логика упрощена · 🚧 честная заглушка.

---

## 1. Обзор и модель
Единый Streamlit-апп: тёмная тема второго разработчика + реальный бэкенд A (логин/JWT, приватность/
шаринг, цепочка гейтов, реестр по зонам, жизненный цикл, инциденты, админка). **Артефакт — центр,
«Реестр» — хаб.** `todo_frontend/` — исходный референс, в рантайме не используется.

**Принципы:** вход только реальный (JWT, роли из `/auth/me`); все запросы с Bearer; данные из
реального API, без mock (где бэкенд не готов — честный плейсхолдер); GET-ы кэшируются (TTL≈4с),
после мутаций кэш сбрасывается.

## 2. Запуск/конфиг
`infra\start.cmd` → `streamlit run ui/app.py :8501`. Env: `GATEKEEPER_URL` (дефолт
`http://localhost:8200`; в Docker `http://backend:8000`), `APP_DEBUG` (на роли не влияет),
`MLFLOW_UI_URL`. Тема — `.streamlit/config.toml` + кастомный CSS в файле. Зависимости: streamlit,
requests, `src/common/controls.py` (GRC-каталог).

## 3. Аутентификация
`main()`: нет токена → `render_login()` (вкладки Вход/Регистрация); иначе `render_app()`.
Роли обновляются из `/auth/me` (кэш TTL≈4с); при кэш-промахе — одна прямая проверка; `401` → logout.
Все вызовы несут `Authorization: Bearer`.

## 4. HTTP-слой и кэш (перформанс)
- `api_get/api_post` — обёртки с Bearer.
- **`_cached_get(path, token, timeout)`** под `@st.cache_data(ttl=4)` — снимает лаг от ререндеров
  Streamlit (на каждый клик скрипт перезапускается; без кэша = шквал синхронных запросов).
- `get_json(path, default)` → кэшированный JSON или default (без mock).
- **`_invalidate()`** (`_cached_get.clear()`) — после логина/мутаций/кнопки «Обновить».
- `_not_implemented(...)` — единый честный плейсхолдер.

## 5. Роли и навигация
`_roles/_has/_clearance`; `PAGE_DEFS` = `(имя, фн, предикат)`, сайдбар-radio только из видимых.
Программная навигация `_goto(page, **pending)` / `_open_artifact(run_id)` (через `_nav_request`/
`_pending_state`/`_artifact_open`). Смена раздела сбрасывает открытый артефакт. Каждая страница — в
`try/except` (ошибка раздела не роняет апп).

## 6. Реестр и страница артефакта (ядро) ✅/🟡
**`page_registry`:** если в сессии есть `_artifact_open` — рендерит страницу артефакта; иначе —
реестр. Реестр: `GET /registry` → артефакты сгруппированы по **зонам** (`ZONE_ORDER`/`ZONE_LABEL`:
черновики/не прошли/ок/выкатка/прод/предыдущие/выведены). **Фильтры:** теги `security.*`
(multiselect), зона, статус проверки, Tier, владелец. Подпись о физ.хранилище (`storage_note`).
Каждый артефакт — карточка с бейджами (Tier/статус/SHARED) и кнопкой «Открыть →».

**`_render_artifact_detail(run_id)`** (паспорт):
- Заголовок: зона, Tier, статус проверки, стадия, бейдж видимости; run_id/владелец/эксперимент.
- Метрики и параметры (lineage).
- **Цепочка гейтов** (`_gate_chain_html`): горизонтальные узлы G1→…→G5 со статусом (✓/✕/∅);
  по каждому гейту — экспандер с `detail`, **логами** (`errbox`) и кнопкой «🔁 Перезапустить гейт»
  (владелец/MLSecOps). Кнопка «🛡 Перепройти security check (вся цепочка)» (владелец).
- **Инциденты артефакта** (таблица из карточки).
- **Выкатка/продакшн** (RBAC: MLSecOps): по стадии — Инициировать выкатку / (HIGH) ожидание
  Human Approve / Approve (не владелец) / Перевести в ПРОД / Откатить / Вывести. Поле «Причина»
  пишется в Audit Trail. Подпись: реального CI нет (плейсхолдер), движение стадий персистится.

## 7. Остальные разделы
- **Дашборд:** счётчики (в проде/прошли/инциденты/события), очередь **«Ожидают Human Approve»**
  (MLSecOps, `/approvals/pending`, «Рассмотреть →» открывает артефакт), статус аудита (CEO),
  рантайм-метрики 🚧.
- **Кабинет:** /me, MLflow-токен (сниппет), последние раны.
- **Мои артефакты:** свои раны (приватность/шаринг); кнопки «Security check», «Открыть доступ»
  (с подсказкой: видимость другим ролям после проверки), «Закрыть доступ», «Открыть в реестре →».
- **История:** фильтры по тегам (тип события/результат/роль), не по строке; кнопка «Проверить
  цепочку»; карточки по статусу.
- **Инциденты:** фильтры (гейт/severity/статус); «Открыть артефакт →»; «Отметить FP» (MLSecOps).
- **Пользователи:** список+роли, назначить роль, создать юзера, выдать доступ к датасету.
- **Карта покрытия / Контур:** GRC-каталог (controls.py), RiskAcceptance, сводка контура.

## 8. UI-хелперы/стиль
Pills `_pill/_spill/_tpill/_sevpill`; `_kind` (статус→цвет, включая stage/zone/tier); карточки
`.card`, узлы цепочки `.gnode/.chain`, `.errbox` для логов; `_when` (ms→дата); `_label`
(run_name/session_name/run_id); `_share_badge`; `_sel` (выбор строки dataframe).

## 9. Контракт «страница → эндпоинт» (адаптеры)
История: `action→type`, `reason/details→detail`. verify_chain: `count`. Карточка артефакта: гейты
из `check_detail.gates`; зона/стадия/Tier/инциденты/is_owner — из карточки. Реестр: зоны из
`zones`, фильтр тегов из `tags`.

## 10. Ограничения
`/verify`, `/train`, рантайм-метрики, S3-хранилище — 🚧 (плейсхолдеры/не подключено). Логика
гейтов — плейсхолдер (PASS), поэтому цепочка обычно зелёная и инциденты обычно пусты. `use_container_width`
даёт deprecation-warning (работает; заменить при апгрейде Streamlit). graphviz-граф lineage в текущей
странице артефакта не используется (метрики/параметры таблицами).

## 11. Как проверялся
`py_compile` (все модули) · TestClient e2e нового потока — **24/24** (реестр-зоны, check→Tier,
MED-авто vs HIGH→HITL с не-владельцем, approvals/pending, инцидент из FAIL-гейта + FP, сброс стадии,
аудит) · Streamlit `AppTest` — логин + все 9 разделов + страница артефакта рендерятся без
необработанных исключений (в т.ч. без бэкенда — graceful).
