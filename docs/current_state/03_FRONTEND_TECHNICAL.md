## 1. Обзор и происхождение

`ui/app.py` — **единый Streamlit-апп** (один файл, ~700 строк). Это результат **слияния** двух
интерфейсов:
- полированный многостраничный UI второго разработчика (тёмная тема, 12 разделов, навигация
  сайдбаром, изначально на mock-данных без аутентификации) — взят как основа внешнего вида и структуры;
- рабочий личный кабинет нашего бэкенда A (логин/JWT, приватность/шаринг артефактов, сканеры,
  админка) — влит как реальная функциональность.

**Три зафиксированных решения слияния:**
1. **Только реальный логин** — нет демо-переключателя ролей; роли строго из `/auth/me` (RBAC).
2. **Рабочие вкладки бэка интегрированы** логически (переименованы/слиты), ничего не потеряно.
3. **Честные пустые заглушки** — все `MOCK_*` удалены; где бэкенд-ручка заглушка, показывается
   «не реализовано», а не фейковые записи.

`todo_frontend/` — исходный репозиторий второго разработчика — оставлен как референс, не используется в рантайме.

## 2. Технологии и зависимости

- **Streamlit** — UI-фреймворк (один процесс, сайдбар-навигация, `st.*` компоненты).
- **requests** — HTTP-вызовы к бэкенду (с Bearer-токеном).
- **`src/common/controls.py`** — pure-data каталог контролей (импортируется как `CTRL`), для
  разделов «Карта покрытия» и «Контур». Если импорт не удался — эти разделы скрываются.
- Тема: `.streamlit/config.toml` (base=dark, акцент `#6366F1`) + объёмный кастомный CSS внутри файла.
- Доп. библиотек (sklearn/onnx и т.п.) фронту НЕ нужно.

Импорты обёрнуты в `try/except` (`_HAS_STREAMLIT`): без установленного streamlit модуль
компилируется (`py_compile`), но не запускается.

## 3. Запуск и конфигурация

Запускается как часть стенда: `infra\start.cmd` поднимает `streamlit run ui/app.py --server.port 8501`
и прокидывает env. Переменные:

| Переменная | Дефолт | Назначение |
|---|---|---|
| `GATEKEEPER_URL` | `http://localhost:8200` | адрес бэкенда (в Docker — `http://backend:8000`) |
| `APP_DEBUG` | `false` | дев-флаг (на ролевую модель НЕ влияет — вход только реальный) |
| `MLFLOW_UI_URL` | `http://localhost:5000` | ссылка «Открыть MLflow UI» в Кабинете |

> Дефолт `GATEKEEPER_URL` — **8200** (см. бэкенд-доку §14: 8000 на Windows зарезервирован Hyper-V).
> В `docker-compose.yml` UI получает `http://backend:8000` явно — контейнерная сеть не затронута.

UI открывается на http://localhost:8501.

7. **Навигация/рендер** — `PAGE_DEFS`, `render_app()`, `main()`.

## 5. Аутентификация в UI

- **Вход обязателен.** `main()`: если в `st.session_state` нет `token` → `render_login()`, иначе
  `render_app()`.
- `render_login()` — две вкладки: **Вход** (`/auth/login` → сохраняет `token`, `username`, `roles`
  в session_state) и **Регистрация** (`/auth/register`; роль выдаст MLSecOps).
- **Роли обновляются на каждом рендере:** `render_app()` дергает `/auth/me`; `200` → обновляет
  `st.session_state["roles"]` (учёт выдачи/отзыва роли без релогина); `401` → `_logout()` (токен
  истёк/невалиден). Сбой сети → рендерим по последним известным ролям.
- `_logout()` чистит token/username/roles и делает rerun.
- **Все запросы несут `Authorization: Bearer <token>`** (через `_auth_headers`).

## 6. HTTP-слой и политика данных

- `api_get(path, **kw)` / `api_post(path, json/files, headers, **kw)` — обёртки над `requests`,
  инжектят Bearer-токен. Возвращают `requests.Response`.
- `get_json(path, default=None, timeout=5)` — GET → распарсенный JSON или `default`. **Без
  mock-фолбэка** — если бэкенд недоступен/ответ не ok, вернётся `default` (обычно `{}`/`[]`), и
  страница покажет честную пустоту/заглушку.
- `_not_implemented(what, endpoint=None, note=None)` — единый честный плейсхолдер
  («🚧 раздел готов в UI, бэкенд-ручка ещё не реализована»). Используется на всех 🚧-страницах.

**Политика:** real-data-first, никаких фейковых данных. Пустой бэк → честная пустая страница.

---

## 7. Ролевая модель и гейтинг страниц

- `_roles()` — текущие роли из session_state; `_role()` — первая (для отображения); `_has(*roles)`
  — есть ли пересечение; `_clearance()` — макс. уровень по `ROLE_LEVEL`.
- **`PAGE_DEFS`** — список `(имя, функция, предикат_видимости)`. `render_app()` фильтрует по ролям
  и строит сайдбар-radio только из видимых разделов.

| Раздел | Предикат | Кому видно |
|---|---|---|
| Дашборд | всегда | всем (CEO — спец. read-only вид) |
| Кабинет | всегда | всем |
| Мои артефакты | DS/DE/MLSecOps | разработчикам и безопаснику |
| Верификация | DS/DE/MLSecOps | разработчикам и безопаснику |
| Реестр / Паспорт / История / Находки | всегда | всем (read) |
| Инструменты | DS/DE/MLSecOps | запуск гейтов |
| CI/CD логи | MLSecOps | безопаснику |
| Деплой / Approve | MLSecOps | безопаснику |
| Пользователи | MLSecOps | безопаснику |
| Карта покрытия / Контур | если есть `controls.py` | всем |

Пользователь **без роли** видит общедоступные разделы + баннер «вам ещё не назначена роль».
CEO по предикатам получает обзорные read-разделы.

## 8. Навигация

- Сайдбар: бренд, имя пользователя, «пилюли» ролей, кнопка «Выйти», `st.radio` по видимым разделам
  (`key="active_page"`), адрес бэкенда.
- **Программные переходы** (кнопки «Открыть →» на дашборде): `_goto(page, **pending)` кладёт
  `_nav_request` (+ опц. `_pending_state`) в session_state и делает rerun; `render_app()` применяет
  их до создания radio. Если целевой раздел не входит в видимые — игнор.
- Каждая страница рендерится в `try/except` — ошибка раздела не роняет весь апп («Ошибка раздела: …»).

## 9. Постраничный разбор (14 разделов)

### Дашборд — `page_dashboard()` ✅/🚧
Реальные счётчики: модели (`/models`), события (`/events`), открытые находки (`/findings`→0),
клиренс. CEO (без MLSecOps) — отдельный read-only вид + статус целостности Audit Trail
(`/events/verify_chain`). Кликабельные карточки → `_goto`. Блок «Мониторинг рантайма (G6/G7)» →
`_not_implemented` (нужен рантайм-слой C).

### Кабинет — `page_cabinet()` ✅
(слиты бывшие «Личный кабинет» + «MLflow раны».) `/auth/me` (имя, роли, клиренс);
«Получить MLflow-токен» (`/auth/token` → Python-сниппет); таблица последних ранов
(`/mlflow/runs?limit=50`); ссылка на MLflow UI.

### Мои артефакты — `page_artifacts()` ✅ (логика check — 🟡)
`/artifacts` → `{mine, shared_with_me, my_clearance}`. По каждому своему рану — экспандер с
кнопками: «Запустить security check» (`/artifacts/{id}/check`), «Поделиться» (`/share`, активна
только при `check==passed`, с мультиселектом кастомных ролей), «Снять шаринг» (`/unshare`).
Внизу — таблица «Доступно мне» (расшаренное другими). `_share_badge()` рисует видимость
(🔒 приватный / 🔗 роли / 🔗 клиренс ≥ N).

### Верификация — `page_verify()` 🚧
Таб 1 «Верификация модели»: форма (модель, run_id, git_sha, причина) → `POST /verify`. Бэкенд
возвращает `TODO`/`passed:null` → честный плейсхолдер «deep-verify ещё не реализован» + JSON ответа.
Таб 2 «Раннер гейтов» (MLSecOps): `_not_implemented("/scan")` с подсказкой, что покнопочный запуск
гейтов работает в «Инструментах».

### Реестр — `page_registry()` ✅ (данные пусты)
`/models` (MLflow Registry) → таблица `{модель, версии}`. Пусто → честная заглушка «реестр пуст».
Примечание: детальный паспорт/lineage требует ручек реестра (🚧).

### Паспорт — `page_passport()` 🚧
Селектор модели из `/models`; детальный паспорт (Tier/lineage/версии/история) →
`_not_implemented` (нужны `/models/{name}/versions`, `/datasets/{key}`).

### История — `page_events()` ✅
`/events?limit=100` + **адаптер полей** бэкенда → ожидаемые UI: `action→type`, `reason`(или
`details` как JSON)`→detail`, `asset/result/ts` как есть. Фильтр по активу. Кнопка «Проверить
цепочку хешей» (`/events/verify_chain`, адаптер `count`). Рендер карточками по статусу
(ok/blocked/error/pending) с иконками.

### Находки — `page_findings()` 🚧
Фильтры (гейт/severity/статус) + `/findings`. Сейчас пусто → `_not_implemented` (db.add_finding /
`/findings` в разработке; гейты уже отдают evidence в «Инструментах»).

### CI/CD логи — `page_cicd()` 🚧 (MLSecOps)
`_not_implemented("/cicd/runs")` + ссылка на GitHub Actions (если задан `GITHUB_REPO`). Триггер
гейтов в Actions уже работает через `/ci/trigger`, но retrieval статусов/логов обратно — TODO.

### Инструменты — `page_scanners()` ✅
(бывшая рабочая вкладка «Сканеры».) Запуск гейтов на реальных артефактах через `/ci/trigger`:
- G1 Data Gate — на выбранном CSV (список из `/files`, дефолт `data/train_m1_clean.csv`);
- G2 Code Gate — на коде (`target="."`);
- G3 Dependency Gate — на зависимостях.
Обрабатывает оба режима ответа: `github_actions` (ссылка) и `local` (рендер report: PASS/FAIL по
каждой проверке + detail/SKIP). Плюс загрузка CSV (`/upload`). Внизу — справочная таблица
инструмент→гейт→угроза (gitleaks/bandit/pip-audit/trivy/modelscan/cosign/pandas/redis/evidently).

### Деплой / Approve — `page_deploy()` 🚧 (MLSecOps)
RBAC реальный (не-MLSecOps не попадёт). Модели на деплой берёт из `/models` (пусто). Сами операции
деплоя/approve/rollback/retire → `_not_implemented` (ручки — заглушки).

### Пользователи — `page_users()` ✅ (MLSecOps)
(слита бывшая «Админка».) `/admin/users` → таблица `{логин, email, роли}` (адаптер shape бэка).
Формы: «Назначить роль» (`/admin/roles`), «Создать пользователя» (`/admin/users`), «Выдать доступ
к датасету» (`/admin/access`, +can_export). `403` без роли MLSecOps.

### Карта покрытия — `page_coverage()` ✅
Из `CTRL` (`controls.py`): метрики покрытия (closed/total, %, live/accepted/planned), прогресс-бар,
таблица контролей (ID, контроль, угрозы, гейт/слой, статус, тесты, стандарты ATLAS/OWASP/NIST/ФСТЭК)
с выбором строки → тесты+стандарты. MLSecOps может «Принять остаточный риск» (RiskAcceptance) —
сейчас фиксируется локально (`CTRL.set_accepted`), персист в БД GRC — TODO. CEO видит итоговый %.

### Контур — `page_contour()` ✅
Сводка: состояние (ТРЕВОГА/OK по числу открытых находок из `/findings`), контроли в контуре, %
покрытия. Карточки рантайм/инфра-контролей из `controls.py` со статусами. Живые рантайм-метрики
(PSI/429) — появятся, когда рантайм-слой начнёт отдавать их в бэкенд.

## 11. UI-хелперы и стиль

- **Pills:** `_pill(text,kind)`, `_spill(status)` (по статусу), `_tpill(tier)`, `_sevpill(severity)`.
- `_kind(s)` — маппинг статуса → цветовой класс (ok/bad/warn/info/muted); покрывает значения бэка
  (ok/blocked/pending/error) и доменные (passed/shared/private/candidate/…).
- Карточки `.card`, этапы `.stage`, `.errbox`, моноширинный код — через кастомный CSS.
- `_sel(event)` — индекс выбранной строки `st.dataframe(on_select=...)`.
- **graphviz-DOT** (`_lineage_dot`, `_versions_dot`, `_finding_dot`) — заготовки для графов lineage/
  версий/находок; на пустых/заглушечных страницах не вызываются, активируются, когда появятся
  данные реестра/находок.

## 12. Ограничения и заметки

- **🚧-разделы** (Верификация, Паспорт, Находки, CI/CD логи, Деплой, частично Дашборд) показывают
  честные заглушки до реализации соответствующих ручек бэка.
- **`use_container_width`** даёт deprecation-warning в свежем Streamlit (удаляют после 2025-12-31),
  но работает; оставлено для единообразия с остальным кодом — заменить на `width=...` массово при
  обновлении Streamlit.
- **graphviz** рендерится Streamlit из DOT-строки (системный graphviz не требуется для строк).
- Доступ к 🚧-ручкам без бэка не роняет апп — ошибки ловит `try/except` уровня раздела.

## 13. Как проверялся

- **`py_compile`** — синтаксис `ui/app.py` (+ `controls.py`).
- **Streamlit `AppTest`** (официальный харнесс): экран входа + **все 14 разделов** рендерятся без
  единого необработанного исключения, в т.ч. при выключенном бэкенде (graceful degradation).
- **End-to-end через TestClient/HTTP**: формы ответов реальных ручек (`/auth/me`, `/auth/token`,
  `/events`, `/events/verify_chain`, `/admin/users`, `/models`, `/findings`, `/artifacts`)
  совпадают с тем, что потребляют страницы (включая адаптеры).
