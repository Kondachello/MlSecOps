# 14 — Фронтенд / UI (Streamlit)

Цель UX: **единый процесс**, а не 10 разрозненных кнопок. Видно, как сценарий проходит стадии
и проверки. Полноценная видимость в вебе — главный носитель ценности для жюри.

## 14.1 Вкладки

| Вкладка | Содержимое |
|---|---|
| **Кабинет / Верификация** | форма: модель (выпадашка из MLflow), Run ID, Git SHA, датасет (авто), причина → кнопка «Отправить на верификацию безопасности» / «Просканировать ресурс всеми применимыми образами». Показ отчёта по гейтам в реальном времени (прогресс джоб/шагов). |
| **Паспорт модели (G0)** | поля паспорта: owner, Tier, источник, назначение, версии, lineage (данные↔код↔модель), история проверок, кто сделал. Кликом — провалиться в находки/события. |
| **Реестр** | список моделей/датасетов с фильтром по статусу/Tier/owner. Что в проде, чьё, какой версии. |
| **История событий** | Audit Trail (`events`): фильтры по активу/типу/результату/актору. Кнопка «проверить целостность лога» (hash-chain). |
| **Находки (Findings)** | все сработки гейтов. Можно смотреть по одному активу или по системе (открытые/закрытые). У сканера видно «300 запусков, 5 находок». Кнопки: «Показать причину» (рендер JSON-evidence), «Отметить как False Positive» (MLSecOps, +reason), «Перезапустить проверку». |
| **Инструменты / Сканеры** | список инструментов (gitleaks, pip-audit, modelscan, …): что делает каждый, к какой угрозе привязан, история его сканирований и статистика. |
| **Деплой / Approve** | для Tier=HIGH — кнопка **Approve Deploy** (видна только MLSecOps); статус карантина и причина; откат/retire. |
| **Доступы (админка)** | регистрация пользователей, назначение ролей, выдача доступа к датасетам, право `data_export`. Только MLSecOps. |
| **Дашборд / Мониторинг** | runtime-метрики, дрейф (PSI), всплески атак (429), статус защищённости. Отдельный read-only вид для CEO («✅ всё супер»). |

## 14.2 Сквозные UX-принципы

- **Видна связь проверка → угроза.** У каждого инструмента/находки — к какой угрозе из модели
  угроз он относится (маппинг из [`08_THREAT_MODEL.md`](08_THREAT_MODEL.md)).
- **False Positives — first-class.** У заблокированного актива всегда виден JSON-отчёт гейта
  (причина блока), есть отметка FP и перезапуск. Это снимает боль MLOps «безопасники всё сломали».
- **Кнопка «взять датасет/модель из сервиса»** — выдаёт управляемую копию с проверкой доступа.
- **Поле «причина изменения»** — обязательно для изменяющих действий (пишется в `events`).

## 14.3 Роли в UI

- Кнопки/вкладки скрываются по роли (Approve/админка/деплой — только MLSecOps; CEO — read-only).
- **Demo-переключатель «режим разработчика / режим MLSecOps»** — за `DEBUG`-флагом, для показа
  функционала на демо. В боевом конфиге выключен (роль — только из аутентификации). См.
  [`06_IDENTITY_AND_AUTH.md`](06_IDENTITY_AND_AUTH.md) §6.6.

## 14.4 Текущее состояние (если переносим существующий код)

Базовый Streamlit уже имел вкладки Паспорт/События/Датасеты/Находки — их переиспользуем и
расширяем формой верификации, Approve, админкой доступов и дашбордом.
