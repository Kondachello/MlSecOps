# 08 — Модель угроз (паспорт безопасности системы)

Паспорт безопасности по формату куратора (8 колонок). Документ читаемый и для не-технарей:
показывает **активы**, **от чего защищаемся**, **последствия для бизнеса** и **чем закрываем**.
Легенда гейтов — [`07_SECURITY_GATES.md`](07_SECURITY_GATES.md). Рабочие карточки с планом
реализации каждой угрозы — `08b_threat_model_dev.md` (опционально, развёрнутые описания).

## 8.1 Колонки

1. **Актив** — что защищаем. 2. **Поверхность атаки** — точка входа. 3. **Уязвимость** — дыра.
4. **Угроза** — что делает атакующий. 5. **Последствия** — ущерб бизнесу. 6. **Риск** = Вероятность × Ущерб.
7. **Техники** — MITRE ATLAS/ATT&CK (+ФСТЭК). 8. **Митигация/Gate** — чем закрываем.

## 8.2 Приоритизация

«Сделайте минимум и потом расширяйте». 4 тира:

- **P0 (MVP, без него не выходим на демо):** #10, #8, #3, #4, #25, Audit Trail, Gate-перед-продом+Tier/HITL.
- **P1 (низковисящие):** #1, #2, #5, #6, #11, #22, #23.
- **P2 (practice-maxxing):** #9, #12, #13, #24, #26, #14, #20, #19.
- **P3 (GenAI/агенты, только если берём 4-ю модель):** #7, #15, #16, #17, #18, #21.

Обоснование фокуса: на демо за 10–15 минут нужен **цельный конвейер** (датасет → обучение →
деплой → атака в рантайме), а не 26 разрозненных проверок. P0 закрывает 4 сценария ТЗ сквозным
флоу; остальное навешивается на тот же конвейер без смены архитектуры. GenAI — последним, т.к.
фокус кейса — не(де)генеративный ИИ.

## 8.7 Соответствие 4 «фичам для жюри»

1. **Единая история событий** → `events` (hash-chain), вывод в UI. (P0)
2. **HITL** → `Tier=HIGH` не деплоится автоматом, Approve у MLSecOps. (P0)
3. **False Positives** → в UI причина блока = JSON-отчёт гейта, отметка FP, перезапуск. (сквозное)
4. **Runtime-защита** → Redis rate-limit, `attack_sim.py` → `429`. (P1)

## 8.9 Честные пределы защиты (важно для доверия жюри)

Мы НЕ заявляем «всё закрыто». Явно фиксируем, что **не** предотвращается полностью, а только
**детектируется и атрибутируется**:

- **Трояны в весах модели** (не pickle-RCE, а вредоносное поведение, зашитое в обученные веса):
  modelscan/picklescan их **не ловят**. Закрываем: метка источника + обязательный HITL + red-teaming
  + полная атрибуция. (#3, частично)
- **Инсайдер с валидными кредами:** действует «как легитимный пользователь». Не предотвращается
  аутентификацией; ограничивается RBAC (least privilege) и **полностью логируется** для
  расследования. (#22, #24)
- **Целостность лога — tamper-evident, не tamper-proof:** hash-chain делает подделку *заметной*,
  но приложение всё равно имеет право INSERT. Усиление — отзыв UPDATE/DELETE на БД-роли. (#24)
- **Governed copy данных:** после выгрузки на ноут разработчика контроль платформы заканчивается;
  право `data_export` ограничивает, но не отменяет доверие к сотруднику. (#2, #12)

Такая честность сильнее, чем галочка «закрыто», которая разваливается от одного вопроса.
